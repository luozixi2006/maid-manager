# 3.0.9：聊天与工作并列、应用内操作、可缩放陪伴

## 使用入口

- 首页左侧“聊天”、右侧“工作”。工作页直接输入要求，过程与结果显示在同一会话；左上角打开历史，右上角新建工作。
- 工作输入框上方展开权限：本任务内自动允许常规操作；文件读取另行选择目录并授权。已保存的旧服务和聊天不清空；新安装/新增服务不再预填 DeepSeek 地址或模型。
- 工作权限 → 允许操作的应用：全选、清空、更新未完成任务的授权。全选不包括应用自身、系统权限与安装界面，不自动授予任何安卓系统权限。
- 悬浮窗顶部拖动位置，右下角缩放，窗口大小本地保存。只改变布局宽高，文字自然换行，输入内容不清空。
- 人设编辑：随人设 / 固定间隔 / 随机间隔（15–1440 分钟）；“测试一次问候”使用已保存的人设和配置的真实模型，消息保存到聊天。
- 工作与陪伴设置 → 屏幕陪伴 → 结合当前页面陪伴：单独选择观察应用，开启系统无障碍，开启悬浮窗，再明确授权这一次会话。展开的悬浮窗可点“看看当前页面并和我说句话”，也可暂停。

## 操作范围和边界

- 使用已有持久化任务引擎，不新建后端，不更换模型协议。打开应用使用原生 Intent；应用内的观察、搜索、输入、滚动使用已授权无障碍服务。
- 搜索步骤是：发现真实包名 → 打开 → 读取真实节点 → 搜索入口 → 填写 → 重新观察 → 输入框搜索动作/搜索按钮 → 读取结果。不能把打开应用当成搜索完成，不能把可见结果当作穷尽整个应用数据库。
- 常规批量授权只在一个任务里有效；允许文件创建/整理、已选应用的打开、读取页面和浏览。搜索框输入与提交、搜索/导航按钮通过真实节点的保守检查后才可自动运行。不明按钮、发送、发布、付款、删除、通知正文仍逐次确认；不做账号登录、验证码或支付认证代办。中断且结果不明的操作不盲目重放。
- 页面陪伴读取当前前台应用的可见无障碍文字，不截图、不录屏。编辑框不作为陪伴上下文；密码页、验证码页、锁屏、未选择的应用不读取。必要文字直接发送到用户配置的当前人设模型，原始页面文字不写入日志/数据库。生成的问候仍是本地聊天记录。
- 页面文字是不可信数据，不是用户授权或工具指令。此读取模块本身没有任务执行工具。关闭悬浮窗/进程退出后观察会话关闭，重启不自动恢复。
- 自动问候使用人设的间隔和原有安静时段，未回复不连发，最近聊天有冷却；系统调度可能延迟，间隔不是准点闹钟。主动问候检查时才能结合当前页面，不会每秒请求模型。手动测试可立即调用一次模型，可能产生服务费用。

## 验证范围

- 新增自动测试覆盖空服务默认值与已有配置保留、任务授权持久化、文件独立同意、不同联系间隔、窗口缩放边界、真实无障碍动作的模拟页面搜索、观察应用白名单/敏感页面拒绝、工作区侧栏与明暗主题。
- Android 原生视图测试检查悬浮窗缩放后输入保留、页脚边界、展开拖动；Compose 渲染报告在 `app/build/reports/ui`。
- 当前电脑未连接安卓设备。真实 B 站或其他第三方 App 的界面、搜索框可访问性、厂商后台限制、键盘与跨应用行为仍需要实机验证，不能保证任意软件所有页面均可自动操作。

## 平台依据

- [Android AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)：通过系统授权的节点动作读取/操作页面。
- [交互窗口读取标志](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo)：选择最上层应用窗口，避免把自己的悬浮窗当成目标页面。
- [后台启动限制](https://developer.android.com/guide/components/activities/background-starts)：只在前台、可见悬浮窗或已连接无障碍服务场景发起原生应用启动；系统拒绝时暂停，不绕过。
