# 3.0.8：以陪伴为主的悬浮窗口

## 入口

- 人设编辑里的「让这个人设主动来找我」是日常问候的唯一开关。性格和最近聊天决定话题与联系倾向，不用编写任务规则。通知与安静时段在人设列表内。
- 「任务与陪伴」分为「帮我办事」「屏幕陪伴」「事件提醒」；事件提醒只是额外的手机事件规则，不代替人设陪伴。
- 屏幕悬浮窗分为聊天和办事。聊天显示同一份本地会话（窗口展示最近30条，应用内可查看全部），关闭再开仍保留。角色消息和任务结果不混在同一张工作面板。
- 悬浮窗可提交任务、逐次确认、暂停和继续。首次提交明确展示文件范围和数据使用确认；仍由已有受限工具层执行，不能绕过系统授权。系统分享/日历等高影响操作仍需系统界面确认。

## 文件与办公

- 目录浏览、名称搜索、常用目录中文提示、最近目录；选择后保存准确路径，新任务复用该范围，已创建任务不被后续选择改变。
- 任务创建出的文件夹提供直接定位入口。规划器先列出真实名称，不猜英文路径；默认用用户语言命名新分类，并复用已有目录。
- 文件查找不限格式。照片、音频、压缩包等可按名称/类型移动、复制和改名；不假装识别其中内容。
- 增加 DOCX / XLSX / PPTX 文字读取，保留 PDF / TXT / Markdown / CSV / JSON 等文本读取。Office 不运行宏、公式或外部资源；不支持旧二进制 DOC/XLS、OCR、音视频理解或直接编辑 Office 排版。
- Office 展开上限4MB，每部分1MB，最多40部分。文件读取上限20MB。递归文件查找最多8层/10000项；目录搜索6层/4000目录/200结果；超大范围需要分目录处理。
- 文件事件扩展为选定目录内所有格式，4层内最多2000文件；只比较元数据，不上传正文。升级后重新建立一次基线，避免把已有文件误当新增。

## 主动消息兼容与隐私

旧全局开关的实际选择会保留：原来关闭的不会因升级自动产生付费请求。重新在人设内明确开启后，不再受旧全局开关限制。人设首次开启后安排5至15分钟的检查，实际执行受 Android 后台调度、网络、免打扰和最近聊天影响，不保证准时弹出。后续由性格倾向调整，限制至少一小时发送间隔；上一条主动消息未回复时不连发。模型判断无话可说时可跳过。

开启人设主动聊天时，会按需请求系统通知权限。新安装的角色消息通知频道采用高重要性；已有频道和用户手动关闭/降级的通知设置由 Android 保留，不绕过。悬浮窗未开启时，能否横幅弹出仍取决于系统通知设置。

本地记忆关闭时，不会把记忆交给悬浮聊天或主动问候模型。聊天失败保留已发送消息，并写入原错误报告，不输出密钥。新功能不需要服务器、云存储或新增 Android 权限类型。

## 悬浮窗口与测试边界

聊天区独立滚动，输入栏固定在窗口底部；根据系统栏和键盘可用空间调整窗口尺寸，兼容旧版 adjustResize。实现参考 [Android WindowManager](https://developer.android.com/reference/android/view/WindowManager.LayoutParams) 和 [键盘可见性](https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/visibility)。

展开态顶部拖动条、头像和标题区均可拖动。拖动不重建输入框、不切换收起状态；展开窗口不强制吸附边缘，小头像仍吸边。位置限制在可用屏幕范围内。模拟测试发送真实触摸事件核对展开状态、窗口坐标及输入控件是否被保留。

自动测试覆盖本地 HTTP 会话续聊、实际主动问候 Worker、目录持久化/越界保护、各种格式事件、Office 正文/共享字符串/不安全XML/展开大小限制，以及实际悬浮服务渲染函数的窗口布局和模拟键盘 Insets。图像输出在 app/build/reports/ui。测试中的模型回复是本地模拟接口，不代表使用用户真实密钥完成在线生成；模拟窗口不是实机跨应用测试。没有连接手机时，仍需用户确认厂商悬浮权限、真实键盘、后台保活和实际 Provider 表现。
