# 3.0.14 更新下载闪退修复

## 根因与范围

OPPO Find X7 Ultra 上的 3.0.11 在下载 3.0.13 更新包时连续三次出现相同崩溃：`OutOfMemoryError`，分配大小为 130768984 字节，栈顶为 Ktor 2.3.12 `SavedCallKt.save`。APK 为 130768970 字节，应用 Java 堆上限为 256 MiB。

原代码先调用 `client.get()`，它会保存完整响应；后续 `bodyAsChannel()` 再分块写文件已经太晚。与 API 密钥、手机存储授权和安装签名无关。

## 修复

- APK 使用 `prepareGet().execute {}`，以 8 KiB 缓冲直接写 `.part` 文件，不在内存保留整个包。
- 下载失败或取消时结束响应读取并清理临时文件；完成后替换目标文件，不提前删除已有缓存。
- 校验空响应、声明长度、实际字节数；APK 最大 512 MiB。
- 更新列表和清单同样有读取上限，分别为 1 MiB 和 256 KiB；检查工作移到 IO 线程。
- 大文件总超时允许 30 分钟，但单次连接和无数据等待仍有限制。保留 HTTPS、SHA-256、包名、版本和原签名校验。
- 不修改聊天、长期记忆、模型、人设、手表感知或配对业务。

## 自动回归

更新模块测试覆盖真实 Ktor OkHttp 执行链上的 144 MiB 懒生成响应、下载中途进度门控、无 Content-Length、取消、截断、404、空包、超大响应与更新清单选择/读取上限。不用一次性内存数组伪造大文件，也不访问外部服务。

修复前已发生闪退的旧版本可能无法从应用内下载本补丁。应通过同签名 APK 覆盖安装，不能卸载旧版或清除数据。
